# 0013: Document tree listing

**Epic:** [0002 Document store](../description.md) · **Depends on:** 0010, 0012 · **Milestone:** M1

## Goal

Return everything the sidebar needs in one read: kind, path, title, status,
epic (derived from the path) and optional feature binding.

## Build

- `DocEntry { path, kind, title, status, epic, feature }`; `Tree { layout_exists, docs }`.
  For a ticket, `epic` is the directory name from
  `sdlc/epics/<epic>/tickets/<ticket>.md`; for other kinds it is `null`.
- `DocStore::tree()` walks the allowed layout: core files, each epic's
  `description.md`, every `tickets/*.md` under it, decisions and features. It
  reads each file, takes the title from the first ATX H1 outside front matter,
  and parses front matter.
- Title fallback: humanized file name (`0007-add-export` → `Add export`) when
  no H1 exists.
- Sorting: core in fixed order (PRD, architecture, conventions, AGENTS), epics
  by numeric directory prefix, tickets within an epic by numeric prefix,
  decisions by number, features by title.
- Skip files that fail `DocPath` or cannot be read; log at debug/warn. Never
  fail the whole tree because one file is odd.
- `layout_exists` is true when the `sdlc/` directory exists; details for
  onboarding come in 0026.

## Already in place

- Read, hash, front matter, layout (0010, 0012, 0008).

## Acceptance criteria

- [ ] Empty project returns `layout_exists: false`, empty docs.
- [ ] Core entries appear only when the file exists.
- [ ] Feature and ticket statuses appear; invalid status is `null`.
- [ ] Epic statuses appear; a ticket's `epic` is its parent directory name.
- [ ] Ticket `feature` is exposed as a slug without `.md` when present.
- [ ] Ordering is deterministic across runs.
- [ ] An unreadable or invalidly named file does not break the response.
- [ ] A ticket in a directory without `description.md` is still listed, with a
  warning and its derived epic directory.

## Tests

- **Unit:** fixture project with all kinds; assert ordering and fields.
- **Unit:** missing H1 fallback; multiple H1s → first wins; H1 inside a fenced
  code block is ignored.
- **Unit:** invalid filename and invalid UTF-8 are skipped.
- **Unit:** ticket with a missing parent `description.md` is listed with its
  derived epic and a warning.
- **Unit:** `layout_exists` for empty, partial and complete layouts.

## Gotchas

- Do not read every file twice; one read supplies title and front matter.
- Limit concurrency when many files exist; a simple sequential loop is fine for
  v1 and easier to reason about.
- H1 parsing must skip front matter and fenced code blocks, or a code sample
  becomes the title.
- Feature rename can orphan a ticket's optional `feature:` link; a ticket's
  epic cannot be orphaned by moving the ticket because the path moves with it.
  A missing Epic `description.md` is the only structural orphan, and 0048
  exposes it.
